---
title: Troubleshooting
description: Resolve common access, configuration, image, and documentation problems.
---

## I cannot sign in

Check the installation address and username with your organizer.
Use the replacement temporary password after an organizer resets your account.
Complete the required password change before trying to open contest data.
Contact the organizer for recovery. There is no email reset flow.

## I can sign in but have no contest access

Ask an organizer to check your session membership and assigned team or staff roles.
Provider access does not grant Minsky session membership.
If you have several sessions, select the intended one in the sidebar.

## I cannot submit a new report

Contestant intake may be closed.
An archived event also prevents changes.
Ask the session admin to check the event and intake state.
For a staff report, select a team from the search suggestions before submitting.

## The page shows Connecting

**Connecting** means that the Realtime subscription is pending.
**Live** means that the subscription is active.
Check the network connection and any displayed request error.
Refresh after connectivity returns.
Before repeating an action, check whether the saved issue already contains it.
Offline capture is not implemented.

## My image upload fails

Use JPEG, PNG, or WebP.
HEIC, GIF, SVG, PDF, and video are unsupported.
Check the session's file, count, and combined size limits.
Check that the event is active and your account still has staff access.
Retry a failed transfer through the displayed control.
Cancel the upload before changing its file or audience.

## A removed image still needs cleanup

Use **Retry removal** as the uploader.
Minsky keeps the cleanup request when storage removal fails.
Do not delete unrelated storage objects or reset the bucket.
An operator should check the attachment function and storage errors if retries continue to fail.

## A new frontend cannot call the backend

For Cloudflare, build with `VITE_BACKEND=cloudflare`.
The browser calls the same origin. Check the Worker, its bindings, and `AUTH_ORIGIN`.
For the Supabase provider, set `VITE_BACKEND=supabase`.
Check its public URL, publishable key, allowed origins, and `ALLOWED_ORIGINS`.
Check that its account and attachment functions use the same reviewed revision as the frontend.
Rebuild the frontend after you change its public connection settings.

## The docs search has no results locally

The search index is generated by the production docs build.
Run `npm run docs:build`, then `npm run docs:preview` from the repository root.
Search is checked against the built site before deployment.

## A documented control is absent

The installation may run an older revision, or your account may lack the required role.
Check [feature status](/reference/status/) and the installation's source revision.
Open pull requests do not imply deployed features.
